One Model, Any Sensor: Sensor Fusion and Few-Shot Generalization for Body-Conducted Speech Enhancement

Audio demonstrations and code for anonymous NeurIPS 2026 submission. All samples are from the Vibravox test set (French speech, unseen speakers). Sample IDs match the dataset for cross-reference.

🎧 Headphones recommended. Spectral artifacts are most audible on headphones. Samples are in French; audio quality differences are perceptible regardless of language comprehension.
Sample selection. Samples were selected programmatically to maximize audible differences between conditions, not cherry-picked. For each demo, we scored all available test samples by a relevant metric and selected the top candidates:
  • Amplitude drift: Ranked by log-spectral distance contrast between amplitude-stable and drifted models.
  • Fusion: Ranked by SI-SDR improvement of the 5-sensor model over unprocessed input on noisy speech (E2).
  • LOO sensor robustness: Ranked by SI-SDR gap between full 5-sensor and forehead-held-out configurations, filtering for positive LOO SI-SDR (graceful degradation, not failure).

Architecture Overview

(a) Each sensor's waveform passes through a shared Conv1d frontend, is modulated by FiLM conditioning on a learned sensor embedding, and optionally attends to other sensors via cross-attention before mean pooling into the backbone. Sensor dropout (p=0.5, min_keep=1) during training forces robustness to arbitrary sensor subsets. (b) At inference, the model accepts any subset of the five sensors. In the leave-one-out setting, every 4-of-5 configuration still exceeds single-sensor baselines.

Body-conducted microphones (throat, temple, forehead, in-ear) capture speech through tissue and bone vibration. The signals are noisy and bandwidth-limited. Our model fuses any subset of these heterogeneous sensors into clean airborne-quality speech.

Input: (B, S, T) — S sensors, each a mono waveform at 16 kHz

For each sensor s:
    h_s = GELU(Conv1d(x_s))           # shared frontend (same weights for all sensors)
    h_s = γ(e_s) ⊙ h_s + β(e_s)      # FiLM conditioning on learned sensor embedding

Sensor dropout: randomly zero sensors during training (p=0.5, min_keep=1)
Cross-attention across sensor tokens (optional)
Mean pooling across sensors → (B, T, D)

8× MambaBlock (pre-norm residual, causal, O(1) memory per step)
    Optional: gated STFT spectral injection at layers [1, 3, 5]

LayerNorm → Conv1d(D, 1) + skip connection → (B, 1, T) enhanced output

3.9M parameters (base) / 5.1M (with STFT branch). Real-time on a single GPU. Causal Mamba backbone enables streaming inference.

1. Amplitude Drift: The Scale-Invariant Loss Failure Mode

SI-SDR, the standard loss for speech enhancement, is scale-invariant — it ignores absolute output amplitude. When input and target have different natural amplitudes (as in body-conducted → airborne conversion), this causes amplitude drift: the model learns correct waveform shape at incorrect scale, producing spectral distortion and crackling artifacts.

The figure below (from the paper) shows per-sample amplitude ratios. SI-SDR-trained models drift to up to 8.4× reference amplitude. The audio exports below use target-based normalization, so the amplitude is corrected — but the spectral distortion from training at incorrect amplitude is preserved and audible as crackling and harshness.

3. Leave-One-Out Sensor Robustness (Noisy Speech)

The model is robust to sensor absence without retraining — the same weights are used, only the input sensor subset changes. Sensor dropout during training acts as implicit meta-learning over the combinatorial space of sensor subsets. Below: the same model with all 5 sensors vs. with one sensor excluded at inference.

4. Few-Shot Sensor Adaptation

When a new sensor type becomes available, how much data is needed to integrate it? We evaluate a three-stage generalization hierarchy:

  1. Unknown type — The model has never seen this sensor. Uses an out-of-vocabulary embedding + zeroed input. Relies entirely on the remaining 4 sensors.
  2. Known type — The sensor type is identified (e.g., "forehead accelerometer") but no paired recordings are available. Uses the trained FiLM embedding with zeroed input. The correct modulation helps the model better fuse the remaining sensors.
  3. 10 min adapted — Fine-tune only the sensor embedding vector (freeze all other weights) with 10 minutes of paired data. Full 5-sensor performance is recovered.

All sensors converge to ~7.5% WER with just 10 minutes of paired data, matching the full 5-sensor baseline (dashed line). Additional data provides no further improvement.

Key findings: 10 minutes of paired data is sufficient — all sensors converge to ~7.7–7.9% WER, matching the full 5-sensor model (7.58%). Additional data (30/60 min) provides no further improvement. Merely knowing the sensor type ("Known type" column) provides substantial improvement over the unknown baseline (e.g., forehead: 16.14% → 12.37%), because the correct FiLM modulation helps the model better weight the remaining sensors even without signal from the held-out channel.

Connection to meta-learning. Sensor dropout during training implicitly optimizes a meta-learning objective: at each step, the model must perform well on a randomly sampled sensor subset (the "task"). The learned initialization is biased toward representations that are easy to adapt. Fine-tuning a single embedding vector (the "task descriptor") with 10 minutes of data is sufficient because the shared backbone already represents sensor-agnostic speech features.

5. Learned Sensor Embeddings

Figure (from paper): Cosine similarity between learned sensor embeddings. All pairwise similarities are near zero (|cos| < 0.17), indicating the model learns nearly orthogonal representations for each sensor type — maximally distinguishing their transfer functions rather than clustering physically similar sensors.

6. Code

Self-contained model architecture and inference script:

  • model.py — Full sensor-agnostic architecture: shared Conv1d frontend, FiLM conditioning, cross-attention, sensor dropout, Mamba backbone, optional parallel STFT branch with gated spectral injection. No external dependencies beyond PyTorch and mamba-ssm.
  • inference.py — Load a checkpoint and enhance any combination of sensor WAV files.
pip install torch torchaudio mamba-ssm

# Inference with any subset of sensors
python code/inference.py \
    --checkpoint model.pt \
    --input throat.wav temple.wav forehead.wav \
    -o enhanced.wav
